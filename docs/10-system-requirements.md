# Системные требования (для заказчика)

Требования к инфраструктуре заказчика для развёртывания self-hosted поставки
(Veltiq: канбан, база знаний, чат, почта, файлы). Продукт поставляется как набор
Docker-образов; всё ПО (PHP 8.5, PostgreSQL 18, Redis 7, Meilisearch, Reverb,
nginx, ntfy) работает **внутри контейнеров** и на хост отдельно не устанавливается.

> Числа по железу — **ориентировочные рекомендации** для типовой нагрузки. Точный
> расчёт зависит от числа активных пользователей, объёма файлов и включённых модулей.
>
> Веб-фронтенд поставляется уже собранным (`frontend/dist`), поэтому **Node.js/npm на хосте не требуются**
> и фронтенд на сервере не пересобирается.

## 1. Сервер (хост)

| Параметр | Требование |
|----------|-----------|
| ОС | **Linux**, рекомендуется Ubuntu Server 22.04 / 24.04 LTS (x86_64) |
| Docker | Docker Engine 24+ и **Compose v2** (`docker compose`) |
| Прочее | `git`, `openssl`; для NFS-хранилища — `nfs-common` |
| Архитектура | **x86_64** рекомендуется; ARM64 не гарантируется (образ ONLYOFFICE только amd64) |
| Виртуализация | KVM/VMware/Hyper-V или bare metal; **Docker Desktop не поддерживается для прода** |
| Время | Обязательна синхронизация часов (**NTP/chrony**): от неё зависят лицензия, grace-периоды и планировщик |

### 1.1 Аппаратные ресурсы (ориентир)

| Профиль | vCPU | RAM | Диск (SSD) |
|---------|------|-----|------------|
| Пилот, до 25 пользователей | 2 | 4 ГБ | 40 ГБ |
| 25–100 пользователей | 4 | 8 ГБ | 80 ГБ |
| 100–250 пользователей | 8 | 16 ГБ | 200 ГБ |
| 250+ пользователей | 16 | 32 ГБ | 500 ГБ+ (БД/поиск — на отдельных узлах) |

Дополнительно:
- **Файловое хранилище**: объём под загрузки пользователей (`storage_data`) — считать отдельно,
  по фактическому объёму документов.
- **ONLYOFFICE Document Server** (опционально, см. §5): **+2 vCPU, +2–4 ГБ RAM, +10 ГБ диска**.
- **Бэкапы**: заложить место не меньше объёма БД + файлов; по умолчанию хранение 14 дней.

## 2. Сеть и порты

### 2.1 Входящие (публикуются наружу)

| Порт | Назначение | Обязательность |
|------|-----------|----------------|
| **80/tcp** | SPA + API + WebSocket (`ws://`) через nginx | да |
| **8081/tcp** | ntfy — push-уведомления | да |
| **443/tcp** | HTTPS / `wss://` | настоятельно рекомендуется (см. §4) |
| **8082/tcp** | ONLYOFFICE Document Server — **только для диагностики**, приложению не нужен (редактор идёт через 80, `/onlyoffice/`) | не требуется |
| **22/tcp** | SSH для администрирования | да (ограничить по IP при возможности) |

### 2.2 Внутренние (НЕ публиковать в интернет)

`5432` (PostgreSQL), `6379` (Redis), `7700` (Meilisearch), `8080` (Reverb), `9000` (PHP-FPM)
доступны только внутри Docker-сети.

### 2.3 Исходящие (из сервера наружу)

- **HTTPS 443** к серверу лицензий (активация, heartbeat, CRL) — если используется онлайн-режим.
- **UDP 123** (NTP) — синхронизация времени.
- Опционально: **SMTP** (модуль почты/уведомления), **1С** (`ONE_C_BASE_URL`),
  **Flare** (`flareapp.io`, трекинг ошибок), доступ к серверу **SMB/SFTP/FTP/WebDAV**
  для подключённого файлового хранилища.

## 3. Клиентские рабочие места

### 3.1 Браузер (SPA)
- Chrome / Edge / Firefox — последние 2 мажорные версии; Safari 16+.
- Разрешение от 1280×720. JavaScript обязателен.

### 3.2 Android-клиент (APK)
- **Android 7.0 (API 24)** и выше (targetSdk 35).
- Для авто-обновления in-app нужна установка из неизвестных источников.

### 3.3 Windows-клиент (EXE / MSI)
- **Windows 10 / 11, x64**. Среда выполнения JVM (JDK 17) поставляется внутри пакета —
  отдельная установка Java не требуется.
- MSI-обновления ставятся поверх (`upgradeUuid` фиксирован).

## 4. Домен, TLS и имена

- **Домен + A-запись** на публичный IP (либо сертификат на IP через ACME).
- Без TLS WebSocket работает только как `ws://`; с TLS — `wss://` (клиент выбирает схему
  автоматически по `window.location.protocol`).
- При включении HTTPS обновить: `APP_URL`, `SESSION_SECURE_COOKIE=true`,
  `SESSION_DOMAIN`, `SANCTUM_STATEFUL_DOMAINS`, `CORS_ALLOWED_ORIGINS`.

## 5. Опциональные компоненты

| Компонент | Что требует |
|-----------|-------------|
| **ONLYOFFICE Document Server** | отдельный контейнер; редактор отдаётся через тот же origin — `ONLYOFFICE_URL=/onlyoffice` (nginx проксирует на контейнер), общий `ONLYOFFICE_JWT_SECRET`; **не** `localhost` и не фиксированный публичный IP; +2 vCPU / +2–4 ГБ RAM |
| **ntfy** | входит в поставку (порт 8081, авторизация включена) |
| **1С** | входящий контур `/api/v1/integration/1c/*`: `ONE_C_TOKEN` и/или `ONE_C_HMAC_SECRET`, опц. `ONE_C_ALLOWED_IPS`; исходящий доступ к `ONE_C_BASE_URL` |
| **Файловое хранилище (адресом)** | доступ сервера по `smb://`, `sftp://`, `ftp(s)://`, `webdav(https)://`; учётные данные вводятся в админке и хранятся зашифрованными |
| **SMB/CIFS или NFS (монтирование, legacy)** | для NFS — пакет `nfs-common` на хосте и экспорт с записью под uid/gid **33**; для SMB — монтирование CIFS |
| **SMTP / почтовый модуль** | релей или ящик с учётными данными SMTP |

> Инструменты предпросмотра (`smbclient`, ImageMagick, poppler, ffmpeg, p7zip) уже в образе
> приложения — на хост их ставить не нужно.

## 6. Лицензирование и время

- Онлайн-режим требует исходящего **HTTPS 443** к серверу лицензий; при недоступности сети
  продукт работает до истечения токена + grace.
- Офлайн-режим (air-gapped): сеть не требуется — лицензия переносится **файлом**
  (request-код → подписанный license-файл).
- **Синхронизация времени обязательна**: проверяются `not_before` / `expires_at`, откат часов
  назад фиксируется как аномалия.

## 7. Хранилище данных и бэкапы

- Данные хранятся в Docker-volume: `pgdata`, `redisdata`, `meilisearchdata`, `storage_data`,
  `ntfydata`; каталог `./updates` (bind-mount) — бинарники обновлений клиентов.
- **Бэкап** (`scripts/backup.sh`): PostgreSQL в custom-формате, `storage_data`, дамп Meilisearch;
  по умолчанию хранение **14 дней** (`RETENTION_DAYS`).
- Рекомендуется ежедневный cron + контроль свободного места.

## 8. Что должен предоставить заказчик

- [ ] Сервер с Linux (Ubuntu LTS) и Docker + Compose v2, доступ по SSH.
- [ ] Публичный IP, при желании — домен и TLS-сертификат.
- [ ] Открытые порты 80, 8081 (+ 443, если включён TLS).
- [ ] NTP-синхронизацию часов.
- [ ] (Опционально) SMTP, контур 1С, сетевое файловое хранилище, ONLYOFFICE.
- [ ] Список пользователей/администраторов и правила доступа.
- [ ] Секреты: `APP_KEY`, пароли БД, `REVERB_APP_SECRET`, `MEILI_MASTER_KEY`, пароль ntfy.

## 9. Ограничения

- Хост-ОС — только **Linux**; Docker Desktop (Windows/macOS) для прода не поддерживается.
- Приоритетная архитектура — **x86_64**; на ARM64 сборка не гарантируется (ONLYOFFICE — amd64).
- NFS поддерживается только через монтирование (в админке `nfs://` недоступен).
- `ftps://` — только explicit TLS (порт 21); implicit FTPS (990) не поддерживается.
- Минимальная версия Meilisearch зафиксирована (`v1.56.1`); обновление — только через
  dump/restore + `search:reindex`.
- Один канал обновлений на платформу: одновременно публикуется только одна сборка
  Android/Windows.
