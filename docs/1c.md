**Назначение:** выдача сведений справочника «Контрагенты» внешним системам (весь справочник постранично или выборка по отбору).
**Дата документа:** 17.11.2026
**Статус:** реализовано, требуется доработка контракта (см. раздел 11).

## 2. Контракт операции

### 2.1. Операция

```
GetCounterparties(INN, DescriptionPart, Offset, Portion) -> string
```

Возвращает JSON-документ, сериализованный в строку (`xs:string`). Операция одна — и для выгрузки всего справочника, и для выборки по отбору: незаполненные параметры означают «отбор не применять».

### 2.2. Параметры

| Параметр | Тип (WSDL) | Обязательный | Семантика | Поведение при пустом/некорректном |
|---|---|---|---|---|
| `INN` | string | нет | Точное совпадение с `Справочник.Контрагенты.ИНН` | `Null`/`""` → отбор по ИНН не применяется |
| `DescriptionPart` | string | нет | Подстрока в `Наименование` **или** `НаименованиеПолное` (без учёта регистра, `%...%`) | `Null`/`""` → отбор по наименованию не применяется |
| `Offset` | number | нет | Количество пропускаемых записей (смещение) | `Null`/не число/`< 0` → `0` |
| `Portion` | number | нет | Размер порции | `Null`/не число/`<= 0` → `100`; `> 1000` → `1000` |

Особенности:
- Параметры принимаются и как число, и как строка (значение нормализуется в коде).
- Логика отбора: `(ИНН = "") ИЛИ (ИНН = &ИНН)`; `(шаблон = "") ИЛИ (Наименование ПОДОБНО &Шаблон) ИЛИ (НаименованиеПолное ПОДОБНО &Шаблон)`. Спецсимволы `%` и `_` в `DescriptionPart` **не экранируются** — работают как шаблон `ПОДОБНО`.

### 2.4. Поля ответа

| Поле | Тип | Источник |
|---|---|---|
| `Total` | Число | Всего записей по отбору (без учёта смещения и порции) |
| `Offset` | Число | Фактически применённое смещение |
| `Portion` | Число | Фактически применённый размер порции (после ограничения 1000) |
| `Counterparties` | Массив | Записи текущей порции |

Поля контрагента:

| Поле | Тип | Реквизит / правило |
|---|---|---|
| `Ref` | Строка | `Ссылка.УникальныйИдентификатор()` — UUID без фигурных скобок |
| `Code` | Строка | `Код` |
| `Description` | Строка | `Наименование` |
| `FullDescription` | Строка | `НаименованиеПолное` (в УТ синоним «Сокращенное юр. наименование») |
| `INN` | Строка | `ИНН` |
| `KPP` | Строка | `КПП` |
| `LegalPhysicalPerson` | Строка | **Представление** перечисления `ЮрФизЛицо` (не имя значения) |
| `RegistrationCountry` | Строка | **Представление** `СтранаРегистрации` |
| `Partner` | Строка | **Представление** `Партнер` |
| `HeadCounterpart` | Строка | **Представление** `ГоловнойКонтрагент` |
| `RegistrationNumber` | Строка | `РегистрационныйНомер` |
| `TaxNumber` | Строка | `НалоговыйНомер` |
| `OKPOCode` | Строка | `КодПоОКПО` |
| `InternationalDescription` | Строка | `НаименованиеМеждународное` |
| `TranscriptionDescription` | Строка | `НаименованиеВТранскрипции` |
| `AdditionalInformation` | Строка | `ДополнительнаяИнформация` |
| `DeletionMark` | Булево | `ПометкаУдаления` |
| `ContactInfo` | Массив | ТЧ `КонтактнаяИнформация` (пустой массив, если контактов нет) |

Поля `ContactInfo`:

| Поле | Тип | Источник |
|---|---|---|
| `Kind` | Строка | `Вид.Наименование` (например «Телефон», «Адрес») |
| `Presentation` | Строка | `Представление` — готовое к показу значение |
| `Value` | Строка | `Значение` |
| `PhoneNumber` | Строка | `НомерТелефона` |
| `Country` | Строка | `Страна` |
| `Region` | Строка | `Регион` |
| `City` | Строка | `Город` |

**Политика пустых значений:** все незаполненные строковые реквизиты отдаются пустой строкой `""`, никогда не `null`. Отсутствующие ссылки (нет партнёра, нет страны) — тоже `""`. Это упрощает разбор на клиенте, но не позволяет отличить «не заполнено» от «пустая строка» (для 1С это одно и то же).

**Ссылочные поля отдаются представлениями, а не UUID.** Если внешней системе нужны идентификаторы партнёра/страны/головного контрагента — это отдельная доработка (см. п. 11).

## 3. Правила выборки

1. **Только элементы справочника**: `ЭтоГруппа = Ложь`. Группы не выгружаются и в `Total` не входят.
2. **Помеченные на удаление выгружаются** с `DeletionMark = true`. Отдельного параметра «исключить помеченные» нет.
3. **Сортировка**: `Наименование`, затем `Ссылка` — стабильная, поэтому постраничная выгрузка не «дублирует» и не «теряет» записи.
4. **Постраничность**: клиент запрашивает порциями, увеличивая `Offset` на `Portion`, пока не выполнится `Offset >= Total`.
5. **Ограничения порции**: по умолчанию 100, максимум 1000 записей за вызов.
6. Если `Total <= Offset` — запрос данных не выполняется, возвращается пустой массив (защита от лишней нагрузки).

## 4. Алгоритм работы сервиса

1. Нормализация параметров (`СтрокаИзЗначения`, `ЧислоИзЗначения`), ограничение порции.
2. Запрос количества: `ВЫБРАТЬ КОЛИЧЕСТВО(*) ... ГДЕ <условие отбора>` → `Total`.
3. Если `Total > Offset` — запрос данных с тем же условием, сортировкой, пропуском `Offset` строк и остановкой после `Portion` строк.
4. Для полученной порции — один запрос по ТЧ `КонтактнаяИнформация` с условием `Ссылка В (&СписокКонтрагентов)`, группировка в `Соответствие` по контрагенту.
5. Сборка структур, сериализация через `ЗаписатьЗначениеJSON()` (платформа 8.3.23+, режим совместимости расширения 8.3.27).

Количество обращений к БД на один вызов: 3 (количество + данные + контактная информация), независимо от размера порции.

## 5. Аутентификация и права

- Анонимный доступ к ИБ, в которой есть пользователи, платформа не разрешает: и вызов операции, и получение `?wsdl` требуют аутентификации.
- При публикации выбирается «Аутентификация 1С:Предприятия» (логин/пароль пользователя ИБ, HTTP Basic) либо «Аутентификация ОС».
- Свойство «Права» у объекта `WebService` не заполнено → сервис доступен любому пользователю ИБ; фактический состав данных ограничен ролями и RLS этого пользователя.
- **Рекомендация:** отдельный служебный пользователь с минимальными правами (чтение `Справочник.Контрагенты` и связанных `Партнеры`, `СтраныМира`, `ВидыКонтактнойИнформации`).
- При отсутствии прав на справочник клиент получит SOAP Fault с ошибкой доступа.

## 7. Примеры вызова

### 7.1. Без параметров (весь справочник, первая порция)

```xml
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:c="http://gertorg.ru/exchange/counterparties">
  <soapenv:Body>
    <c:GetCounterparties/>
  </soapenv:Body>
</soapenv:Envelope>
```

### 7.2. С отбором

```xml
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:c="http://gertorg.ru/exchange/counterparties">
  <soapenv:Body>
    <c:GetCounterparties>
      <c:INN>7701234567</c:INN>
      <c:DescriptionPart>ромаш</c:DescriptionPart>
      <c:Offset>0</c:Offset>
      <c:Portion>50</c:Portion>
    </c:GetCounterparties>
  </soapenv:Body>
</soapenv:Envelope>
```

Можно передать любое подмножество элементов: непереданные приходят как `Null` и трактуются как «отбор не применять» / значения по умолчанию.

### 7.3. curl

```bash
curl -s -u "user:pass" \
     -H "Content-Type: text/xml; charset=utf-8" \
     --data @request.xml \
     "http://server/base/ws/CounterpartiesExchange.1cws"
```

`SOAPAction` можно не передавать. В WSDL объявлен как
`http://gertorg.ru/exchange/counterparties#CounterpartiesExchange:GetCounterparties`.

### 7.4. Ответ

JSON приходит внутри элемента `return` в XML-экранированном виде:

```xml
<soap:Body>
  <m:GetCounterpartiesResponse>
    <m:return>{&quot;Total&quot;:1,&quot;Offset&quot;:0,...,&quot;Counterparties&quot;:[...]}</m:return>
  </m:GetCounterpartiesResponse>
</soap:Body>
```

Клиент должен: снять XML-экранирование (`&quot;` → `"`, `&amp;` → `&`) → распарсить как JSON.

### 7.5. Из 1С

```bsl
Определения = Новый WSОпределения("http://server/base/ws/CounterpartiesExchange.1cws?wsdl", "user", "pass");
Прокси = Новый WSПрокси(Определения, "http://gertorg.ru/exchange/counterparties",
	"CounterpartiesExchange", "CounterpartiesExchangeSoap");
Прокси.Пользователь = "user";
Прокси.Пароль = "pass";

ВсеКонтрагенты = Прокси.GetCounterparties("", "", 0, 100);
ПоИНН          = Прокси.GetCounterparties("7701234567", "", 0, 100);
```

Имя точки подключения (4-й параметр `WSПрокси`) обязательно — берётся из WSDL (`<wsdl:port name="...">`), у сервисов 1С обычно `<ИмяСервиса>Soap`.

### 7.6. Python (requests)

```python
import json, xml.sax.saxutils as sx, requests

body = """<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
          xmlns:c="http://gertorg.ru/exchange/counterparties">
  <soapenv:Body><c:GetCounterparties><c:INN>7701234567</c:INN></c:GetCounterparties></soapenv:Body>
</soapenv:Envelope>"""

r = requests.post("http://server/base/ws/CounterpartiesExchange.1cws",
                  data=body.encode("utf-8"),
                  headers={"Content-Type": "text/xml; charset=utf-8"},
                  auth=("user", "pass"))
```

Далее из ответа извлекается текст `return` и разбирается как JSON.

## 8. Ошибки

| Ситуация | Что получит клиент |
|---|---|
| Неверные учётные данные / нет аутентификации | HTTP 401 от веб-сервера |
| Нет прав на справочник | SOAP Fault с ошибкой доступа к данным |
| Внутренняя ошибка (например, недоступна БД) | SOAP Fault, текст платформы |
| Отбор ничего не нашёл | Успешный ответ: `Total = 0`, `Counterparties = []` |
| `Offset` за пределами | Успешный ответ: `Total > 0`, `Counterparties = []` |

Прикладных кодов ошибок в ответе нет — всё через SOAP Fault.

## 9. Тест-кейсы (приёмка)

| № | Вход | Ожидание |
|---|---|---|
| 1 | без параметров | `Portion = 100`, `Counterparties` ≤ 100, `Total` = кол-во элементов справочника без групп |
| 2 | `Portion = 5000` | `Portion = 1000`, записей ≤ 1000 |
| 3 | `Portion = -5` | `Portion = 100` |
| 4 | `Offset = -1` | `Offset = 0` |
| 5 | `Offset = Total` | `Counterparties = []`, `Total` прежний |
| 6 | `INN` существующего | ровно 1 запись с этим ИНН |
| 7 | `INN` несуществующего | `Total = 0` |
| 8 | `DescriptionPart = "ромаш"` | попадания по наименованию и по полному наименованию |
| 9 | контрагент с телефоном/адресом | `ContactInfo` заполнена, порядок по `Kind` |
| 10 | контрагент без контактов | `ContactInfo = []` |
| 11 | помеченный на удаление | присутствует, `DeletionMark = true` |
| 12 | группа справочника | в выдаче отсутствует |
| 13 | полная выгрузка циклами по 100 | сумма порций = `Total`, дублей и пропусков нет |
| 14 | без аутентификации | HTTP 401 |
| 15 | пользователь без прав на справочник | SOAP Fault |

## 10. Нефункциональные замечания

- Вызовы к БД: 3 на запрос, не зависят от размера порции.
- `ПОДОБНО '%...%'` по наименованию индексы не использует — на больших справочниках отбор по подстроке линейный. Если станет узким местом: перейти на полнотекстовый поиск или ограничить длину `DescriptionPart`.
- Кэширования и ограничения частоты вызовов нет.
- Журналирование вызовов не ведётся (только стандартный журнал регистрации платформы).

## 11. Открытые вопросы и доработки

| № | Приоритет | Вопрос | Комментарий |
|---|---|---|---|
| 1 | Высокий | **Типы параметров операции не заданы** | Тип возврата — `xs:string`; у параметров XDTO-тип не проставлен (инструментарий не позволяет). В EDT открыть операцию и указать `String / String / Number / Number`, иначе WSDL может уйти с `anyType` и клиенты получат неудобный контракт |
| 2 | Средний | Ответ — JSON-строкой, а не XDTO-структурой | Типизированный XDTO-пакет (`Counterparty`, `ContactInfo`) не создан. Если нужен строгий типизированный WSDL — сделать XDTO-пакет и перевести операцию на него |
| 3 | Низкий | Имя объекта без префикса `МС_` | Замечание валидатора EDT. Оставлено осознанно — чище имя сервиса и URL публикации. Переименование = `МС_CounterpartiesExchange` |
| 4 | Средний | Ссылочные поля — только представления | Нет UUID партнёра, страны, головного контрагента, вида контактной информации. Добавить поля `*Ref` при необходимости |
| 5 | Низкий | Нет фильтра по дате изменения | Для инкрементальной выгрузки потребуется `ДатаИзменения` (или регистр изменений) |
| 6 | Низкий | Нет параметра «исключить помеченные на удаление» | Сейчас клиент фильтрует сам по `DeletionMark` |
| 7 | Низкий | Спецсимволы `%` и `_` в `DescriptionPart` не экранируются | В языке запросов `ПОДОБНО` нет штатного экранирования; при необходимости — заменять на `[%]`/`[_]` или использовать `СтрНайти` |
